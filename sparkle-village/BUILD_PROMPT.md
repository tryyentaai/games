# Sparkle Village — execution brief

Act as a senior children's game designer, early-literacy content author, elementary math specialist, illustrator, accessibility engineer, and release engineer. Execute these responsibilities sequentially and challenge the implementation against the acceptance checks. Build and ship the working game; a concept deck is not a deliverable.

Audience: a seven-year-old using an iPhone, with kindergarten, first-grade, and second-grade practice selected independently for math and reading. Treat these as selected practice targets, not a comprehensive curriculum or diagnostic assessment.

Experience: a delightful illustrated village with three animal neighbors, three mission themes (pet care, a little shop, and a story garden), short six-step adventures, a companion collection, and earned decorations placed visibly in the village. Use an original cohesive vector illustration system, warm paper, soft greens, lilac, peach, and butter yellow. Large comfortable touch controls. Actual visual rewards and saved world changes matter more than ornamental dashboards.

Learning: independent math and reading controls; math-only, reading-only, and mixed play; parent-selected or adaptive difficulty within the chosen grade. Every challenge offers a worked example using a different problem, practice, corrective explanation, an application to the neighbor's goal, and later spaced review. Generate varied math problems with verified answers. Reading content must be human-authored with appropriate spelling patterns, literal comprehension, sequence, and inference; do not teach guessing from pictures. Expose tap-to-hear and automatic narration. Never report narrated or hinted answers as independent reading. Record first-attempt success, assisted completion, skipped work, listening use, and per-skill history. Adaptive advancement requires repeated independent success in distinct completed sessions, never a one-question jump.

Math targets: K counting, comparison, sums and differences within ten, shape properties; grade 1 sums and differences within twenty, tens/ones, missing values, measurement; grade 2 sums/differences within one hundred, two-step situations, time, coins, and hundreds/tens/ones. Reading targets: K CVC, initial sounds and basic high-frequency words; grade 1 digraphs, blends, silent-e and short connected text; grade 2 affixes, two-syllable words, longer text, event order, and reasons. Each grade must change the actual problem bank. Explain that the included targets sample the grade rather than claiming complete coverage.

Child safety and autonomy: no accounts, ads, analytics, purchases, social features, lives, deadlines, or streak punishment. Reward practice and allow skipping. Offer a stopping point after every adventure. Local profiles, separate settings and worlds, pet names, and automatic save after every meaningful action. Parent settings must include a clear progress ledger and save export/import. A simple adult arithmetic gate is a navigation guard, not a security boundary.

Technical: dependency-free HTML/CSS/ES modules; relative paths for GitHub Pages under /games/sparkle-village/; scoped service worker; manifest; Apple Home Screen icon; reduced motion and keyboard support. Speech uses device voices; offline voice availability is device-dependent and disclosed. Core content and assets must have no remote dependencies. Preserve existing repository content.

Acceptance: exercise every grade/subject/theme combination and inspect generated answers, distractors and reading uniqueness; verify independent versus assisted scoring, persistence and profile isolation, mission resumption, adaptive constraints, decoration transactions, completion idempotence, safe import validation, and offline asset coverage. Run available interaction checks; report browser verification limitations truthfully. Publish to the existing games repository and verify live HTTP responses before handing over the link.
